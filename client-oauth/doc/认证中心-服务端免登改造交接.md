# 认证中心（cloud-auth-platform-auth）服务端改造交接

> 用途：SDK 侧（cloud-auth-client-oauth）已改为「登录 / 注册 / 验证码类免登接口统一走 sa-token **pushS 消息总线**」，
> 需要认证中心在服务端注册对应的消息 handler，并把短信限流从 `@RateLimiter` 注解改造为「仅发送成功后才锁」的 Redis 守卫。
> 本文档给 **cloud 项目所在窗口/会话** 使用：按下面 4 处落盘，改完执行 `mvn compile` 验证。

---

## 背景（为什么这么改）

- 子系统运行在小程序 / Android，无法浏览器跳转认证中心，且登录界面自定义。
- 认证中心 `/login`、`/loginByPhone`、`/register` 挂了 `@ApiEncrypt`（RSA+AES 握手），SDK 明文透传会被 `CryptoFilter` 拦成 403。
- `@ApiEncrypt` 只由**入站 HTTP filter** 强制；服务端消息 handler 里**进程内直调** `tokenController.login(...)` 不经过该 filter，天然绕开加密校验。
- `/sso/pushS` 只校验 `client + sign`（密钥是每个客户端本就配置的 secret-key），**不校验登录态**、**无需下发 RSA 公钥**。
- 登录用 **ticket 桥接**：服务端登录成功后 `createTicketAndSave(...)` 返回一次性 ticket，SDK 复用现成的 `doLoginByTicket(ticket)` 完成本地登录 + session 填充，登录内核零改动。

> 注意：网关的「免登录放行」配置 ≠ 总线 handler。总线按 `type` 查找处理器，服务端**必须** `messageHolder.addHandle(type, ...)` 注册，否则 SDK 发 `type=login` 会报「未能找到消息处理器」。

## 服务端落地进度（本次读 cloud 源码核对）

`configAuth` 共设计注册 12 个 handler。**服务端实际已注册 7 个**：`login`、`loginByPhone`、`register`、`sendSmsCode`、`sendSmsCodeByPhone`、`sendSmsCodeByReset`、`captcha`——这 7 个端到端已可用（`CaptchaController.getCodeForBus()`、`SysLoginService.register` 数据驱动等均已就位）。

**尚需补齐 4 个**（SDK 已发出对应 type，但服务端 `messageHolder` 无 handler、`TokenController` 无方法，调用会报「未能找到消息处理器」）：

| type | 服务端缺什么 | 说明 |
|---|---|---|
| `sendSmsCodeForRegister` | `TokenController.sendSmsCodeForRegister(SendSmsForRegisterBody)` + handler | 面向**未注册**号码，**不得**调 `getUserInfoByPhonenumber`（会因号码未注册报错）；直接生成码存 `CAPTCHA_CODE_KEY + phonenumber` + 限流后下发 |
| `resetPassword` | `TokenController.resetPassword(ResetPasswordBody)` + handler | **整条改密链路服务端缺失**：现仅有 `sendSmsCodeByReset` 下发码，无任何接口消费该码真正落库改密。需按 `phonenumber + smsCode + newPassword` 校验并改密，成功后删除 Redis key 防一码多用 |
| `updatePassword` 【登录态】 | `TokenController.updatePassword(loginId, UpdatePasswordBody)` + handler | SDK 随消息上报顶层 `loginId`；服务端据 `loginId` 定位用户，校验旧密码后改新密码 |
| `refreshToken` 【登录态】 | `TokenController.checkSessionAlive(loginId)` + handler | 续期：校验 `loginId` 会话仍有效（未被踢/禁用）后 `createTicketAndSave(client, loginId, null)` 重新签票，SDK 再桥接登录 |

**已取消 1 个**：`loginByWechat`——SDK 已改为**复用通用 `login` handler**（body 里 `grantType=xcx`，服务端 `IAuthStrategy` 路由到已有 `XcxAuthStrategy`），服务端**不必**单独注册 `loginByWechat`。但 `XcxAuthStrategy` 目前是半成品，需补：① `appSecret` 不再写死占位串（按 appid 从配置/DB 取）；② `getUserInfoByOpenid(openid)` 的匹配/绑定实现；③ 调用方 client 的 `sys_client.grant_type` 需包含 `xcx`。

## 1. 新增 `SmsSendGuard.java`

路径：`cloud-auth-platform-auth/src/main/java/io/gitee/chenshaogui/cloudauth/auth/util/SmsSendGuard.java`

```java
package io.gitee.chenshaogui.cloudauth.auth.util;

import io.gitee.chenshaogui.cloudauth.common.redis.utils.RedisUtils;
import lombok.AccessLevel;
import lombok.NoArgsConstructor;

import java.time.Duration;

/**
 * 短信发送限流守卫（Redis，按手机号维度）。
 *
 * <p>与框架的 {@code @RateLimiter} 注解不同：本守卫只在【短信实际发送成功后】才写入冷却锁，
 * 发送失败不占用额度、用户可立即重试，避免出现“验证码没发出去却被锁 60 秒”的问题；
 * 同时提供当日总量上限，双重防护短信轰炸。</p>
 *
 * @author sgchen
 */
@NoArgsConstructor(access = AccessLevel.PRIVATE)
public class SmsSendGuard {

    /** 冷却锁 key 前缀：发送成功后短期锁定 */
    private static final String LIMIT_KEY = "sms:send:limit:";

    /** 当日计数 key 前缀：按发送目标累计当日发送条数 */
    private static final String DAY_KEY = "sms:send:day:";

    /** 冷却时间（秒）：同一号码发送成功后需等待的时间 */
    public static final int COOLDOWN_SECONDS = 60;

    /** 单号码当日发送上限 */
    public static final int DAILY_MAX = 10;

    /**
     * 发送前检查：是否处于冷却期或已达当日总量上限。
     *
     * <p>本方法<b>只读不写</b>，不会消耗额度；额度在发送成功后由 {@link #markSent(String)} 记入。</p>
     *
     * @param target 限流维度（一般是手机号）
     * @return 允许发送返回 {@code null}；否则返回可直接展示给前端的失败原因
     */
    public static String checkBeforeSend(String target) {
        String limitKey = LIMIT_KEY + target;
        if (Boolean.TRUE.equals(RedisUtils.hasKey(limitKey))) {
            long ttl = RedisUtils.getTimeToLive(limitKey);
            long sec = ttl > 0 ? (ttl + 999) / 1000 : COOLDOWN_SECONDS;
            return "验证码发送过于频繁，请 " + sec + " 秒后再试";
        }
        if (RedisUtils.getAtomicValue(DAY_KEY + target) >= DAILY_MAX) {
            return "今日验证码发送次数已达上限，请明日再试";
        }
        return null;
    }

    /**
     * 发送成功后调用：写入冷却锁并累计当日额度。
     *
     * <p>发送失败时<b>不要</b>调用本方法，以保留用户立即重试的能力。</p>
     *
     * @param target 限流维度（一般是手机号）
     */
    public static void markSent(String target) {
        RedisUtils.setCacheObject(LIMIT_KEY + target, 1, Duration.ofSeconds(COOLDOWN_SECONDS));
        String dayKey = DAY_KEY + target;
        // 首次发送时设置当天过期窗口（24 小时）
        if (RedisUtils.incrAtomicValue(dayKey) == 1L) {
            RedisUtils.expire(dayKey, Duration.ofHours(24));
        }
    }
}
```

### 2.2 `sendSmsCode`（用户名+密码维度）
- **删除**方法上的注解行：`@RateLimiter(key = "#smsBody.username", time = 60, count = 1)`
- 在 `sysLoginService.checkLogin(...)` 之后、`String key = GlobalConstants.CAPTCHA_CODE_KEY + userInfo.getUsername();` 之前插入发送前校验；
- 在方法最后的 `return R.ok();` 之前写入冷却锁。

改后方法：
```java
    @PostMapping("/sendSmsCode")
    public R<Void> sendSmsCode(@RequestBody @Validated SendSmsBody smsBody) {
        LoginUser userInfo = remoteUserService.getUserInfo(smsBody.getUsername(), smsBody.getTenantId());
        if(StringUtils.isEmpty(userInfo.getPhonenumber())){
            log.error("登录账号手机号不存在 => {}", smsBody.getUsername());
            return R.fail("登录账号手机号不存在");
        }
        // 检查用户名和密码
        sysLoginService.checkLogin(LoginType.PASSWORD, smsBody.getTenantId(), smsBody.getUsername(), () -> !BCrypt.checkpw(smsBody.getPassword(), userInfo.getPassword()));

        // 发送前限流（只读，不消耗额度）
        String forbid = SmsSendGuard.checkBeforeSend(userInfo.getPhonenumber());
        if (forbid != null) {
            return R.fail(forbid);
        }

        String key = GlobalConstants.CAPTCHA_CODE_KEY + userInfo.getUsername();
        String code = RandomUtil.randomNumbers(6);
        RedisUtils.setCacheObject(key, code, Duration.ofMinutes(Constants.CAPTCHA_EXPIRATION));
        // 验证码模板id
        LinkedHashMap<String, String> map = new LinkedHashMap<>(1);
        map.put("code", code);
        RemoteSms smsResponse = remoteSmsService.sendMessage(userInfo.getPhonenumber(), map);
        if (!smsResponse.getSuccess()) {
            log.error("验证码短信发送异常 => {}", smsResponse);
            return R.fail(smsResponse.getResponse());
        }
        // 仅发送成功后才锁
        SmsSendGuard.markSent(userInfo.getPhonenumber());
        return R.ok();
    }
```

### 2.3 `sendSmsCodeByPhone`（仅手机号，用于手机号登录）

- 在 `String key = GlobalConstants.CAPTCHA_CODE_KEY + body.getPhonenumber();` 之前插入发送前校验；
- 在最后的 `return R.ok();` 之前写入冷却锁。

改后方法：
```java
    @PostMapping("/sendSmsCodeByPhone")
    public R<Void> sendSmsCodeByPhone(@RequestBody @Validated SendSmsByPhoneBody body) {
        LoginUser userInfo;
        try {
            userInfo = TenantHelper.dynamic(body.getTenantId(), () ->
                remoteUserService.getUserInfoByPhonenumber(body.getPhonenumber(), body.getTenantId()));
        } catch (ServiceException | UserException e) {
            log.warn("按手机号发送验证码：查询用户失败 phone={}, err={}", body.getPhonenumber(), e.getMessage());
            return R.fail(e.getMessage());
        } catch (Exception e) {
            log.warn("按手机号发送验证码：查询用户失败 phone={}, err={}", body.getPhonenumber(), e.getMessage());
            return R.fail("该手机号未注册或不可用");
        }
        if (ObjectUtil.isNull(userInfo) || StringUtils.isEmpty(userInfo.getPhonenumber())) {
            log.error("登录手机号不存在 => {}", body.getPhonenumber());
            return R.fail("该手机号未注册或不可用");
        }

        // 发送前限流（只读，不消耗额度）
        String forbid = SmsSendGuard.checkBeforeSend(body.getPhonenumber());
        if (forbid != null) {
            return R.fail(forbid);
        }

        String key = GlobalConstants.CAPTCHA_CODE_KEY + body.getPhonenumber();
        String code = RandomUtil.randomNumbers(6);
        RedisUtils.setCacheObject(key, code, Duration.ofMinutes(Constants.CAPTCHA_EXPIRATION));
        // 验证码模板id
        LinkedHashMap<String, String> map = new LinkedHashMap<>(1);
        map.put("code", code);
        RemoteSms smsResponse = remoteSmsService.sendMessage(userInfo.getPhonenumber(), map);
        if (!smsResponse.getSuccess()) {
            log.error("验证码短信发送异常 => {}", smsResponse);
            return R.fail(smsResponse.getResponse());
        }
        // 仅发送成功后才锁
        SmsSendGuard.markSent(body.getPhonenumber());
        return R.ok();
    }
```

## 3. `CaptchaController.java`

文件：`cloud-auth-platform-auth/src/main/java/io/gitee/chenshaogui/cloudauth/auth/controller/CaptchaController.java`

思路：把原 `getCodeImpl()` 的生成逻辑整体抽到不带限流的 `generateCaptcha()`；HTTP 入口 `getCodeImpl()` 保留 IP 限流并转调 `generateCaptcha()`；新增给总线用的 `getCodeForBus()`（不走 IP 限流，因为总线的来源 IP 恒为子系统后端，用 IP 限流会跨业务串号）。`getCode()` 保持原样。

```java
    /**
     * 生成验证码
     * 独立方法避免验证码关闭之后仍然走限流
     */
    @RateLimiter(time = 60, count = 10, limitType = LimitType.IP)
    public CaptchaVo getCodeImpl() {
        return generateCaptcha();
    }

    /**
     * 供 SSO 消息总线调用：不走 IP 限流，直接生成（或返回未开启标记）
     */
    public CaptchaVo getCodeForBus() {
        CaptchaVo captchaVo = new CaptchaVo();
        if (!captchaProperties.getEnabled()) {
            captchaVo.setCaptchaEnabled(false);
            return captchaVo;
        }
        return generateCaptcha();
    }

    /** 真正的验证码生成逻辑（原 getCodeImpl 方法体搬过来） */
    public CaptchaVo generateCaptcha() {
        // 保存验证码信息
        String uuid = IdUtil.simpleUUID();
        String verifyKey = GlobalConstants.CAPTCHA_CODE_KEY + uuid;
        // 生成验证码
        CaptchaType captchaType = captchaProperties.getType();
        CodeGenerator codeGenerator;
        if (CaptchaType.MATH == captchaType) {
            codeGenerator = ReflectUtils.newInstance(captchaType.getClazz(), captchaProperties.getNumberLength(), false);
        } else {
            codeGenerator = ReflectUtils.newInstance(captchaType.getClazz(), captchaProperties.getCharLength());
        }
        AbstractCaptcha captcha = SpringUtils.getBean(captchaProperties.getCategory().getClazz());
        captcha.setGenerator(codeGenerator);
        captcha.createCode();
        // 如果是数学验证码，使用SpEL表达式处理验证码结果
        String code = captcha.getCode();
        if (CaptchaType.MATH == captchaType) {
            ExpressionParser parser = new SpelExpressionParser();
            Expression exp = parser.parseExpression(StringUtils.remove(code, "="));
            code = exp.getValue(String.class);
        }
        RedisUtils.setCacheObject(verifyKey, code, Duration.ofMinutes(Constants.CAPTCHA_EXPIRATION));
        CaptchaVo captchaVo = new CaptchaVo();
        captchaVo.setUuid(uuid);
        captchaVo.setImg(captcha.getImageBase64());
        return captchaVo;
    }
```

### 4.3 新增自动注入方法：与现有 `configSso` 并列，注册认证类免登 handler
```java
    // 配置SSO：认证类免登消息处理器（登录/注册/验证码短信/图形验证码），供子系统 SDK 走 pushS 总线调用
    @Autowired
    public void configAuth(SaSsoServerTemplate ssoServerTemplate) {

        // 账号密码登录：进程内委托 tokenController.login（绕开 @ApiEncrypt，总线只验签不验登录态），
        // 成功后签发一次性 ticket 回传，SDK 侧用现成 doLoginByTicket 完成本地登录。
        // 普通 login 强制 ignoreCaptcha=false：是否免验证码由“命中哪个 handler”决定，客户端 body 里的同名字段一律被覆盖，防绕过。
        ssoServerTemplate.messageHolder.addHandle("login", (tpl, message) -> {
            String client = message.getString("client");
            String body = applyIgnoreCaptcha(message.getString("body"), false);
            R<LoginVo> login = tokenController.login(body);
            if (login.getCode() != R.SUCCESS) {
                return SaResult.error(login.getMsg());
            }
            String ticket = RemoteSsoServerUtil.createTicketAndSave(client, StpUtil.getLoginId(), login.getData().getAccessToken());
            return SaResult.ok().setData(ticket);
        });

        // 账号密码登录（免图形验证码）：服务端强制 ignoreCaptcha=true，其余与 login 完全一致。
        // SDK 侧对应新增端点 POST /sso/loginByPasswordNoCaptcha（发同 type=loginByPasswordNoCaptcha）。
        ssoServerTemplate.messageHolder.addHandle("loginByPasswordNoCaptcha", (tpl, message) -> {
            String client = message.getString("client");
            String body = applyIgnoreCaptcha(message.getString("body"), true);
            R<LoginVo> login = tokenController.login(body);
            if (login.getCode() != R.SUCCESS) {
                return SaResult.error(login.getMsg());
            }
            String ticket = RemoteSsoServerUtil.createTicketAndSave(client, StpUtil.getLoginId(), login.getData().getAccessToken());
            return SaResult.ok().setData(ticket);
        });

        // 手机号 + 短信验证码登录：同样以 ticket 桥接
        ssoServerTemplate.messageHolder.addHandle("loginByPhone", (tpl, message) -> {
            String client = message.getString("client");
            String body = message.getString("body");
            R<LoginVo> login = tokenController.loginByPhone(body);
            if (login.getCode() != R.SUCCESS) {
                return SaResult.error(login.getMsg());
            }
            String ticket = RemoteSsoServerUtil.createTicketAndSave(client, StpUtil.getLoginId(), login.getData().getAccessToken());
            return SaResult.ok().setData(ticket);
        });

        // 用户注册
        ssoServerTemplate.messageHolder.addHandle("register", (tpl, message) -> {
            RegisterBody registerBody = JsonUtils.parseObject(message.getString("body"), RegisterBody.class);
            R<Void> r = tokenController.register(registerBody);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 发送短信验证码（用户名+密码维度）
        ssoServerTemplate.messageHolder.addHandle("sendSmsCode", (tpl, message) -> {
            SendSmsBody body = JsonUtils.parseObject(message.getString("body"), SendSmsBody.class);
            R<Void> r = tokenController.sendSmsCode(body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 发送短信验证码（仅手机号）
        ssoServerTemplate.messageHolder.addHandle("sendSmsCodeByPhone", (tpl, message) -> {
            SendSmsByPhoneBody body = JsonUtils.parseObject(message.getString("body"), SendSmsByPhoneBody.class);
            R<Void> r = tokenController.sendSmsCodeByPhone(body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 发送短信验证码（注册场景，面向尚未注册的手机号，服务端不校验号码存在性）
        ssoServerTemplate.messageHolder.addHandle("sendSmsCodeForRegister", (tpl, message) -> {
            SendSmsForRegisterBody body = JsonUtils.parseObject(message.getString("body"), SendSmsForRegisterBody.class);
            R<Void> r = tokenController.sendSmsCodeForRegister(body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 发送短信验证码（重置密码）
        ssoServerTemplate.messageHolder.addHandle("sendSmsCodeByReset", (tpl, message) -> {
            SendSmsBySetBody body = JsonUtils.parseObject(message.getString("body"), SendSmsBySetBody.class);
            R<Void> r = tokenController.sendSmsCodeByReset(body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 忘记密码 / 重置密码：凭手机号 + 短信验证码提交新密码完成改密。
        // 验证码由 sendSmsCodeByPhone 下发，存储 key = GlobalConstants.CAPTCHA_CODE_KEY + phonenumber；
        // 本 handler 进程内直调 tokenController.resetPassword(...)（若认证中心该接口挂了 @ApiEncrypt，同样绕开）。
        ssoServerTemplate.messageHolder.addHandle("resetPassword", (tpl, message) -> {
            ResetPasswordBody body = JsonUtils.parseObject(message.getString("body"), ResetPasswordBody.class);
            R<Void> r = tokenController.resetPassword(body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 微信小程序登录：SDK 已复用上面的通用 "login" handler（body 里 grantType=xcx，
        // 由服务端 IAuthStrategy 路由到已有 XcxAuthStrategy），服务端【无需】单独注册 "loginByWechat"。
        // 需保证：① XcxAuthStrategy 的 appSecret 与 getUserInfoByOpenid 已按环境补完；② client.grant_type 含 xcx。

        // 【登录态】修改密码：总线不携带终端用户 token，SDK 已随消息上报 loginId，服务端据此定位用户。
        ssoServerTemplate.messageHolder.addHandle("updatePassword", (tpl, message) -> {
            String loginId = message.getString("loginId");
            UpdatePasswordBody body = JsonUtils.parseObject(message.getString("body"), UpdatePasswordBody.class);
            R<Void> r = tokenController.updatePassword(loginId, body);
            return r.getCode() == R.SUCCESS ? SaResult.ok() : SaResult.error(r.getMsg());
        });

        // 【登录态】刷新令牌/续期：校验 loginId 会话仍有效后重新签发一次性 ticket，SDK 再桥接登录。
        ssoServerTemplate.messageHolder.addHandle("refreshToken", (tpl, message) -> {
            String client = message.getString("client");
            String loginId = message.getString("loginId");
            // 服务端应校验该 loginId 在认证中心仍处登录态（未被踢/未禁用），否则返回错误；
            // 若认证中心有自己的 access token，取回其值；无则传 null（createTicketAndSave 按 loginId 签票）。
            R<Void> check = tokenController.checkSessionAlive(loginId);
            if (check.getCode() != R.SUCCESS) {
                return SaResult.error(check.getMsg());
            }
            String ticket = RemoteSsoServerUtil.createTicketAndSave(client, loginId, null);
            return SaResult.ok().setData(ticket);
        });

        // 图形验证码（不走 IP 限流的总线版本）
        ssoServerTemplate.messageHolder.addHandle("captcha", (tpl, message) ->
            SaResult.ok().setData(captchaController.getCodeForBus()));
    }
```

## 4.4 `loginByPasswordNoCaptcha`：账号密码登录免图形验证码（v1.3.4 追加）

SDK 新增端点 `POST /sso/loginByPasswordNoCaptcha`（入参同 `/sso/loginByPassword`：`username`、`password`），发总线 type=`loginByPasswordNoCaptcha`。上面 §4.3 已给出两个 handler 与 `applyIgnoreCaptcha(...)`；**是否跳过图形验证码完全由“命中哪个 handler”决定，客户端无法用 body 篡改**（普通 `login` 强制 `ignoreCaptcha=false`，`loginByPasswordNoCaptcha` 强制 `true`），因此 `loginByPassword` 的验证码不会被构造报文绕过。服务端还需下面 3 处配套改动：

**(1) `PasswordLoginBody.java` 新增字段**（`io.gitee.chenshaogui.cloudauth.auth.form`）：
```java
    /**
     * 是否跳过图形验证码：仅由服务端 handler 注入（见 SsoServerController.applyIgnoreCaptcha），
     * 客户端上报的同名字段一律被覆盖，不作为可信输入。
     */
    private Boolean ignoreCaptcha;
```

**(2) `PasswordAuthStrategy.login` 验证码闸门改为**（原 `if (captchaProperties.getEnabled())`）：
```java
        // 验证码开关：全局开启、且未被服务端标记为“免图形验证码登录”时才校验。
        // ignoreCaptcha 仅由 loginByPasswordNoCaptcha handler 置 true，普通 login 恒为 false。
        if (captchaProperties.getEnabled() && !Boolean.TRUE.equals(loginBody.getIgnoreCaptcha())) {
            validateCaptcha(tenantId, username, code, uuid);
        }
```

**(3) `SsoServerController` 新增私有辅助方法 `applyIgnoreCaptcha`**（覆写 body 里的 `ignoreCaptcha`）：
```java
    /**
     * 覆写登录 body 中的 ignoreCaptcha 标记：是否免图形验证码由服务端命中的 handler 决定，
     * 忽略客户端上报的同名字段，避免普通 login 的验证码被构造报文绕过。
     *
     * @param body          原始登录 body（JSON）
     * @param ignoreCaptcha true=跳过图形验证码（仅 loginByPasswordNoCaptcha）；false=强制校验
     */
    private String applyIgnoreCaptcha(String body, boolean ignoreCaptcha) {
        Map<String, Object> map = JsonUtils.parseObject(body, Map.class);
        if (map == null) {
            map = new HashMap<>();
        }
        map.put("ignoreCaptcha", ignoreCaptcha);
        return JsonUtils.toJsonString(map);
    }
```
> 复用现有 `login` 的整条策略链（`tokenController.login` → `IAuthStrategy`→`PasswordAuthStrategy`，`grantType=password`），无需新增策略、无需新增 client 授权类型；调用方 client 的 `grant_type` 只要含 `password` 即可（与 `loginByPassword` 相同）。

## 与 SDK 侧的字段/契约对齐

SDK 的 `CloudPlatformHelper` 把每个请求实体（`CloudLoginBo` 等）序列化成 JSON，放进总线的单个 `body` 参数；服务端 handler `message.getString("body")` 原样交给对应 `tokenController` 方法解析。字段名与服务端 Body 类一一对应：

| type | SDK 实体 | 服务端解析类 | 前端需传字段（其余由 SDK 兜底） |
|---|---|---|---|
| `login` | `CloudLoginBo` | `LoginBody`/`PasswordLoginBody` | username、password（开图形码再加 code、uuid） |
| `loginByPasswordNoCaptcha` | `CloudLoginNoCaptchaBo` | `LoginBody`/`PasswordLoginBody` | username、password（**免图形验证码**，实体不含 code/uuid；ignoreCaptcha 由服务端 handler 强制注入，前端无需传） |
| `loginByPhone` | `CloudPhoneLoginBo` | `PhoneLoginBody` | phonenumber、smsCode |
| `register` | `CloudRegisterBo` / `CloudRegisterByCaptchaBo` / `CloudRegisterBySmsBo` | `RegisterBody` | username、password；图形码场景加 code+uuid，短信码场景加 phonenumber+code（**服务端 `SysLoginService.register` 已按 phonenumber 是否非空自动选校验 key，单 handler 不动即可同时支持两种；短信码字段名是 `code`，uuid 为空属正常**） |
| `sendSmsCode` | `CloudSendSmsBo` | `SendSmsBody` | username、password |
| `sendSmsCodeByPhone` | `CloudSendSmsByPhoneBo` | `SendSmsByPhoneBody` | phonenumber |
| `sendSmsCodeForRegister` | `CloudSendSmsForRegisterBo` | `SendSmsForRegisterBody` | phonenumber（号码尚未注册） |
| `sendSmsCodeByReset` | `CloudSendSmsByResetBo` | `SendSmsBySetBody` | username、oldPassword、newPassword |
| `resetPassword` | `CloudResetPasswordBo` | `ResetPasswordBody` | phonenumber、smsCode、newPassword |
| `login`（微信小程序，`grantType=xcx`） | `CloudWechatLoginBo` | `XcxLoginBody` / `XcxAuthStrategy` | xcxCode（小程序临时凭证，**字段名非 code**）、appid 可选 —— **复用 login handler，服务端无需 loginByWechat** |
| `updatePassword` 【登录态】 | `CloudUpdatePasswordBo` | `UpdatePasswordBody` | oldPassword、newPassword（SDK 额外上报 loginId） |
| `refreshToken` 【登录态】 | 无 | —（取 message 里的 loginId） | —（SDK 自动携带 loginId） |
| `captcha` | 无 | —（返回 `CaptchaVo`） | — |

> **`clientId` 已从 SDK 实体中移除、`tenantId` 前端可不传**：SDK 侧 `CloudPlatformHelper.wrapBody` 统一兜底——`clientId` 自动填 SDK 自身配置的 sa-token `client`（即 sys_client.client_id），`tenantId` 不填时默认主租户 `000000`，`grantType` 在实体里也有默认值（password/sms）。因此服务端仍能从 body 拿到 `clientId`/`tenantId`，只是前端无需关心。
>
> sa-token 总线层面的 `client`（用于签名与 ticket 绑定）与 body 里的 `clientId` 都由 SDK 自动注入，两者取值一致。

## 遗留/风险提醒

1. **`@ApiEncrypt` 的 REST 端点保留不动**：`/login`、`/register`、`/loginByPhone` 仍服务认证中心自己的登录页 / 浏览器直连，公钥只在那边用。
2. **`/sso/pushS` 需允许匿名到达**（网关放行 `/sso/**`，现网本如此）；业务级校验与限流已在 handler 内完成。
3. **限流维度**：现按手机号 key；`COOLDOWN_SECONDS=60`、`DAILY_MAX=10` 可按需调整或做成配置项。
4. **多租户 / deviceType**：`tenantId` 随 body 传入并走 `checkTenant`；如需区分小程序 / App 设备，登录时按 `client` / 入参设 device，ticket 会带回 deviceId。
5. **`resetPassword` 依赖认证中心已有改密接口**：handler 直调 `tokenController.resetPassword(ResetPasswordBody)`。若认证中心尚未提供该 REST 方法（仅通过短信码 + 新密码定位用户并落库），需先补上；其校验逻辑与 `sendSmsCodeByPhone` 下发的 `CAPTCHA_CODE_KEY + phonenumber` 验证码一致（校验通过后应删除该 Redis key，防止一码多用）。
6. **登录态接口（`updatePassword` / `refreshToken`）身份来源**：pushS 总线不携带终端用户本地 token，只验 `client + sign`；SDK 已将当前 `loginId` 作为独立消息字段上报，服务端 handler 通过 `message.getString("loginId")` 取值。因消息已由持有 secret-key 的客户端签名，`loginId` 可信；但服务端**不得**信任 body 里可能夹带的任何身份字段，一律以顶层 `loginId` 为准。
7. **`sendSmsCodeForRegister` 与 `sendSmsCodeByPhone` 必须区分**：前者不得调用 `getUserInfoByPhonenumber`（那会因号码未注册而报错），应直接校验验证码 + 限流后下发；后者才需要号码已存在。
8. **`refreshToken` 依赖认证中心会话存活校验**：需服务端实现 `checkSessionAlive(loginId)`；否则 SDK 端点虽可编译/注册，调用会因服务端无 handler / 无业务而失败。截至本次核对，`sendSmsCodeForRegister`、`resetPassword`、`updatePassword`、`refreshToken` **4 个 handler 服务端尚未实现**，上线前需确认补齐。
9. **微信小程序登录走 `login`+`grantType=xcx`（不再新增 loginByWechat handler）**：SDK 已把 `loginByWechat` 改为复用通用 `login` handler；服务端需保证 `XcxAuthStrategy` 可用——当前其 `appSecret` 为写死占位串、`getUserInfoByOpenid` 标注 `todo 需自行根据业务实现`，且调用方 client 的 `grant_type` 必须包含 `xcx`，否则 `tokenController.login` 的 grantType 校验会拒绝。
10. **`loginByPasswordNoCaptcha` 会跳过图形验证码，属显式降安全权衡**：该端点为“子系统自有风控、无需图形码”场景设计，只保留 `checkLogin` 的密码错数锁定（防单账号撞库），但去掉了图形码这道防批量探测的门槛。是否对外暴露、是否叠加 IP/设备维度限流，由子系统自行决定；普通 `login` 的验证码不受影响（已强制 `ignoreCaptcha=false`）。
