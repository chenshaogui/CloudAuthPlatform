## 1. SDK 是什么

`cloud-auth-client-oauth` 是**统一鉴权平台**的客户端 SDK，提供：

| 能力 | 说明 |
|---|---|
| **统一登录** | 跳转到鉴权中心登录，通过 `ticket` 完成本地 `StpUtil.login()` |
| **用户态读取** | `CloudPlatformHelper.getLoginUser()`、`getUserId()` 等，O(1) 内存读取，无远程 |
| **统一注销** | 跨子系统单点注销 / 当前系统单独注销 |
| **公共数据** | 部门 / 字典 / 参数 / 区域 / 公告 / OSS 文件，远程拉取 + 多级缓存 |
| **权限同步** | 服务端改菜单 / 改角色后，客户端自动感知并刷新 Session |
| **操作日志** | 业务线程 O(1) 上报到鉴权中心 `sys_oper_log` 表，零阻塞 |
| **白名单 / 免登录** | `sa-token.permit-paths` 配置（按 URL Ant 模式） |

> **重要约束**：客户端 token 由 **JWT** 模式签发（`StpLogicJwtForSimple`），**密钥必须与鉴权中心一致**。SDK 已默认注入一个占位密钥，生产环境必须在配置中心覆盖。

## 2. 快速开始

### 2.1 引入依赖

业务工程 `pom.xml`：

```xml
<dependency>
    <groupId>io.gitee.chenshaogui.cloudauth</groupId>
    <artifactId>cloud-auth-client-oauth</artifactId>
    <version>1.3.0</version>
</dependency>
```

SDK 已通过 `<optional>true</optional>` 引入 `spring-boot-starter-web`、`sa-token-spring-boot-starter`、`sa-token-sso`、`sa-token-spring-aop`、`sa-token-jwt`、`sa-token-redis-template`、`sa-token-forest` 等，业务方**无需单独声明**。

### 2.2 最小配置（`application.yml`）

```yaml
server:
  port: 8080

spring:
  redis:
    host: 127.0.0.1
    port: 6379
    password:
    database: 0

sa-token:
  token-name: Authorization
  token-prefix: Bearer
  token-style: random-32
  check-same-token: true
  is-log: true
  sso-client:
    client: 66ba2cb22eb6f1006ed2f054f4973955 # 本子系统唯一标识,统一授权中心获取
    secret-key: zOxbjxpYcWC5IkhYuk_Z-PCJ8kYejGt69KOUEZPVVXr
    server-url: https://auth.example.com/cloudAuthPlatform/prod-api/auth
    auth-url: https://auth.example.com/cloudAuthPlatform/index.html#/ssologin
    is-http: true
    
  # 可选：免登录白名单（追加到 SDK 硬默认 /sso/*、/favicon.ico 之后）
  permit-paths:
    - /admin-api/openapi/webhook/**

  # 可选：是否暴露 SDK 内置 Controller（多模块部署时只在登录入口模块开启）
  expose-controller: true
```

### 2.3 启动验证

启动后访问：`GET /sso/getSsoAuthUrl`，返回鉴权中心完整登录 URL 即表示接入成功。

```bash
curl "http://localhost:8080/sso/getSsoAuthUrl?clientLoginUrl=http://localhost:8080/sso/doLoginByTicket&back=/"
# → {"code":200, "data":"https://auth.example.com/sso/auth?client=...&redirect=..."}
```

## 3. 配置项总览

所有配置前缀均为 `sa-token`，与 sa-token 官方配置共用同一命名空间（互不冲突）。

### 3.1 必填 / 强烈建议

| 配置键                                  | 说明 | 默认值 | 备注 |
|--------------------------------------|---|---|---|
| `sa-token.sso-client.secret-key` | JWT 签名密钥 | `abcdefghijklmnopqrstuvwxyz` | **生产必须覆盖**，且与鉴权中心完全一致 |
| `sa-token.sso-client.server-url`     | 鉴权中心地址 | — | 必须以 `http(s)://` 开头 |
| `sa-token.sso-client.client`         | 本子系统标识 | — | 与鉴权中心 `sys_client.client_id` 对应 |

### 3.2 SDK 扩展配置（`CloudProperties`）

| 配置键 | 类型 | 说明 | 默认值 |
|---|---|---|---|
| `sa-token.permit-paths` | `List<String>` | 免登录白名单，Ant 风格 | `[]` |
| `sa-token.expose-controller` | `Boolean` | 是否注册 SDK 内置 `/sso/**`、`/authCenter/**`、`/authCenter/oss/**` | `true` |

**白名单匹配规则**（sa-token 内部 `SaFoxUtil.vagueMatch`）：
- `*`：通配任意字符
- `**`：通配多层路径
- 大小写敏感

**热更新支持**：`permit-paths` 在 Nacos / Apollo 中修改后**无需重启**即可生效，鉴权过滤器每次请求实时读取。

### 3.3 缓存 TTL（高级，按需调优）

| 配置键 | 默认值 | 作用范围 |
|---|---|---|
| `sa-token.cache.ttl-seconds` | `20` | 权限相关（`userInfo` / `routers` / `isRemoteLogin`） |
| `sa-token.cache.reference-ttl-seconds` | `300` | 部门 / 字典 / 参数配置 / 区域 / 公告 / OSS |
| `sa-token.cache.user-ttl-seconds` | `60` | `getUserInfoById` / `getUserListByIds` |
| `sa-token.cache.<apiName>.ttl-seconds` | — | 单接口例外覆盖（最高优先级） |

### 3.4 权限同步

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `sa-token.permission-sync.enabled` | `true` | 是否启用服务端→客户端的权限变更推送感知 |
| `sa-token.permission-sync.interval-seconds` | `20` | 客户端轮询检查间隔（实际读取 `sa-token.cache.ttl-seconds`，此处为兼容键） |

### 3.5 操作日志上报

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `sa-token.oper-log.enabled` | `true` | 总开关 |
| `sa-token.oper-log.flush-interval-ms` | `5000` | 刷盘周期（最小 1000） |
| `sa-token.oper-log.queue-capacity` | `10000` | 内存队列容量（超出丢弃） |
| `sa-token.oper-log.max-batch-size` | `500` | 单次推送条数上限 |

### 3.6 CORS 跨域

| 配置键 | 默认值 |
|---|---|
| `sa-token.client.cors.allowed-origins` | `*` |
| `sa-token.client.cors.allowed-methods` | `POST, GET, OPTIONS, DELETE` |
| `sa-token.client.cors.allowed-headers` | `*` |
| `sa-token.client.cors.max-age` | `3600` |

## 4. 内置 REST 接口

> 全部位于 `io.gitee.chenshaogui.cloudauth.securitycloud.oauth.controller.*`，业务方可**直接覆盖同名 Controller** 自定义返回结构。

### 4.1 SSO 登录流程（免登录，路径 `/sso/*`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sso/getSsoAuthUrl` | 拼装鉴权中心完整登录 URL（前端跳转用） |
| GET | `/sso/doLoginByTicket?ticket=xxx` | 消费 ticket，本地登录，返回登录态 |
| GET | `/sso/login` | 直接跳转鉴权中心登录页（302） |
| GET | `/sso/logout` | 全局单点注销（通知鉴权中心踢下线其他子系统） |
| GET | `/sso/logoutCall` | 鉴权中心回调客户端（必须实现，否则 SSO 全局注销失败） |
| GET | `/sso/logoutByAlone` | 仅注销本系统，不退出其他子系统 |

> 上述路径均在 SDK 硬默认白名单 `[/sso/*, /favicon.ico]` 内，**未登录也可访问**。

### 4.2 鉴权中心查询（需登录，路径 `/authCenter/*`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/authCenter/getMenuRouters` | 当前用户路由 |
| GET | `/authCenter/getLoginUserInfo` | 当前用户完整信息 |
| POST | `/authCenter/clearCache` | 清空 SDK 全部远程调用缓存 |
| GET | `/authCenter/getSsoUrl` | 鉴权中心 URL 三元组（client / serverUrl / authUrl） |
| POST | `/authCenter/listAreas` | 区域编码列表（带条件查询） |
| GET | `/authCenter/getAreaByCode?areaCode=xxx` | 单个区域详情 |
| POST | `/authCenter/listNotices` | 通知公告分页 |
| GET | `/authCenter/getNoticeById?noticeId=xxx` | 公告详情 |

### 4.3 对象存储（需登录，路径 `/authCenter/oss/*`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST（form-data） | `/authCenter/oss/upload` | 单文件上传（字段名 `file`） |
| GET | `/authCenter/oss/getUrlById?ossId=xxx` | 单个文件 URL |
| GET | `/authCenter/oss/getUrlByIds?ossIds=1,2,3` | 多个文件 URL（逗号分隔） |
| GET | `/authCenter/oss/listByIds?ossIds=1,2,3` | 多个文件完整信息 |

> 详细入参/出参字段见 [接口文档](./统一认证平台客户端sdk%20接口文档.md)。

## 5. 核心工具类 `CloudPlatformHelper`

包路径：`io.gitee.chenshaogui.cloudauth.securitycloud.oauth.utils.CloudPlatformHelper`

## 6. Sa-Token 权限注解

SDK 已注册 `CloudAuthPermissionImpl` 作为 `StpInterface` 实现，业务方在 Controller 上直接使用 sa-token 官方注解即可。

### 6.1 `@SaCheckLogin` / `@SaCheckRole` / `@SaCheckPermission`

```java
@GetMapping("/list")
@SaCheckLogin                                                  // 要求登录
public R<List<Xxx>> list() { ... }

@PostMapping("/delete")
@SaCheckRole("admin")                                          // 角色校验（注意：@SaCheckRole 在 Controller 方法上）
public R<Void> delete(@RequestBody XxxBo bo) { ... }

@GetMapping("/export")
@SaCheckPermission("system:user:export")                       // 菜单权限校验
public void export(HttpServletResponse response) { ... }

// 组合：必须同时满足
@SaCheckLogin
@SaCheckRole("admin")
@SaCheckPermission("system:user:query")
public R<...> get() { ... }
```

### 6.2 角色客户端剪裁

`@SaCheckRole` 的角色集合是**按当前请求所属 client 剪裁过的**：

- 全局角色 `superadmin` / `admin` → 原样透传
- 客户端角色 `{currentClientId}-{roleKey}` → 暴露**两种** key（兼容新旧写法）
  - 完整 key：`{clientId}-admin`（旧）
  - 剥离前缀：`admin`（新）
- 其它客户端的角色 → **不暴露**（防跨子系统越权）

业务方推荐用新写法：`@SaCheckRole("admin")` / `@SaCheckRole("user")`。

### 6.3 免登录白名单（`@SaIgnore` 当前不支持，请用 `permit-paths`）

> ⚠️ **当前版本说明**：本 SDK 全局鉴权过滤器（`SaServletFilter`）只支持 **URL 模式白名单**，**不支持** `@SaIgnore` 注解。如需免登录，请通过 `sa-token.permit-paths` 配置项声明。

```yaml
sa-token:
  permit-paths:
    - /admin-api/openapi/webhook/**
    - /public/health
    - /public/**
```

**白名单匹配规则**（sa-token `SaFoxUtil.vagueMatch`）：
- `*`：通配任意字符
- `**`：通配多层路径
- 大小写敏感

**优先级（仅 URL 维度）**：`permit-paths` > `StpUtil.isLogin()`

**热更新**：配置中心（Nacos / Apollo）修改 `permit-paths` 后**无需重启**即可生效 —— 鉴权过滤器每次请求实时读取该字段，由 Spring Cloud 的 `ConfigurationPropertiesRebinder` 在同一个 `CloudProperties` 实例上重新绑定。

> **关于 `@SaIgnore`**：虽然 sa-token 官方在 `SaInterceptor` 里支持 `@SaIgnore` 注解级免登录，但 SDK 出于性能考虑使用 `SaServletFilter`（运行在 Servlet 层，早于 Spring MVC Dispatcher），无法直接感知 HandlerMethod 上的注解。若业务方仍想用 `@SaIgnore`，可在自身工程里注册一个 `SaInterceptor` Bean 与本过滤器并存，详见 [§9 Q4](#q4--saignore-为什么不生效)。

### 6.4 自定义未授权响应

`@SaCheckLogin` 失败时，SDK 全局过滤器会写 401 + JSON：

```json
{
  "code": 401,
  "msg": "登录状态已失效，请重新登录",
  "data": "/sso/login?back=http%3A%2F%2Flocalhost%3A8080%2Fxxx"
}
```

`@SaCheckRole` / `@SaCheckPermission` 失败时由 sa-token 框架抛 `NotRoleException` / `NotPermissionException`，默认 403，**业务方可在自身工程里注册全局异常处理器覆盖**。

## 7. 操作日志上报

```java
import io.gitee.chenshaogui.cloudauth.securitycloud.oauth.operlog.CloudOperLogRecorder;
import io.gitee.chenshaogui.cloudauth.securitycloud.oauth.bean.CloudOperLogVo;

@PostMapping("/delete")
@SaCheckPermission("system:user:delete")
public R<Void> delete(@RequestBody XxxBo bo) {
    // 业务逻辑
    userService.delete(bo.getId());

    // ★ 记录操作日志（业务线程 O(1)，任何异常静默吞掉，不影响主流程）
    CloudOperLogRecorder.record(CloudOperLogVo.builder()
        .title("用户管理")
        .operName(CloudPlatformHelper.getUsername())       // 当前操作人
        .businessType(CloudOperLogVo.BusinessType.DELETE)   // 枚举：ADD/EDIT/DELETE/QUERY/EXPORT/...
        .requestMethod("POST")
        .operUrl("/admin-api/system/user/delete")
        .operParam(JsonUtils.toJsonString(bo))              // 入参（注意脱敏！）
        .build());
    return R.ok();
}
```

> **写入性能**：业务线程仅一次 `BlockingQueue.offer()`，单守护线程 5s 一批异步上报鉴权中心 `sys_oper_log` 表。队列满丢弃新日志，**绝不影响业务**。

## 8. 多模块微服务部署

### 8.1 推荐架构

```
system 模块（登录入口）  ──┐
                          ├── 引入 cloud-auth-client-oauth
                          ├── sa-token.expose-controller: true
infra 模块（公共服务）   ──┤
                          ├── 引入 cloud-auth-client-oauth
                          ├── sa-token.expose-controller: false ← 关闭
gateway 模块            ──┤
                          ├── 不引入 SDK
                          └── 路由分发
```

> **为什么只有登录入口模块开启**：避免多个微服务同时暴露 `/sso/getSsoAuthUrl` 等接口，Nginx 转发时随机路由到某个模块，行为不可预期。

### 8.2 配置

```yaml
# system 模块 application.yml
sa-token:
  expose-controller: true    # 登录入口模块：必须开

# infra / openapi / app 等模块 application.yml
sa-token:
  expose-controller: false   # 非入口模块：必须关
```

### 8.3 多模块间如何共享登录态

sa-token 默认按 `token` 在 Redis 中维持登录态，**多模块共用同一个 Redis 即可共享**。SDK 内部 `StpLogicJwtForSimple` + `sa-token-redis-template` 已默认走 Spring 容器中的 `RedisTemplate`，业务方**保证多个模块的 `spring.redis.*` 配置指向同一个 Redis** 即可。

## 9. 常见问题 FAQ

### Q1. 启动报 `NoUniqueBeanDefinitionException: StpLogic`

业务方自定义了 `StpLogic` Bean（如 sa-token 默认实现），导致与 SDK 的 `StpLogicJwtForSimple` 冲突。**删除业务方自定义的 `StpLogic`**，或显式继承 `StpLogicJwtForSimple`。

### Q2. 登录后调鉴权中心接口报 `token 已被冻结`

`sa-token.dynamic-active-timeout` 未开启。SDK 已默认注入 `true`，若配置中心显式设为 `false` 会覆盖默认值。**确认业务方 yml 中没有 `sa-token.dynamic-active-timeout: false`**。

### Q3. 鉴权中心报 `token 解析失败`

**`sa-token.jwt-secret-key` 与鉴权中心不一致**。联系鉴权中心运维确认密钥并同步。

### Q4. `@SaIgnore` 为什么不生效

本 SDK 全局鉴权过滤器（`SaServletFilter`）**仅按 URL 匹配**白名单，**不读取** Controller 类/方法上的 `@SaIgnore` 注解。sa-token 官方的 `SaInterceptor` 才支持注解级免登录，但它运行在 Spring MVC 调度之后，SDK 为了在更早的 Servlet 层拦截鉴权而未启用 `SaInterceptor`。

**解决方案（三选一）**：

1. **推荐**：改用 `sa-token.permit-paths` 配置项（见 [§6.3](#63-免登录白名录saignore-当前不支持请用-permit-paths)），按 URL Ant 模式声明。
2. **混合模式**：业务方在自己工程里额外注册一个 `SaInterceptor` Bean，与本 SDK 的 `SaServletFilter` 并存（注意：此时 `SaServletFilter` 先于 `SaInterceptor` 执行，未命中白名单的请求会被 `SaServletFilter` 拦截，`@SaIgnore` 仍不会生效——除非把 `SaServletFilter` 里的 `addInclude("/**")` 改为更窄的范围）。
3. **彻底替换**：业务方禁用 SDK 的 `SaServletFilter`（`sa-token.only-login: true` 关闭全局鉴权），自己用 `SaInterceptor` 实现。

### Q5. 接口返回 401 但用户实际已登录

通常是 token 写到 Redis 后被业务方误清理。检查：
- 业务方是否自定义了 `RedisTemplate` Bean 替换了 SDK 使用的实例
- Redis 是否配置了过期策略导致 session 丢失

### Q6. 字典 / 部门 修改后，客户端多久生效

- 默认 5 分钟（参考数据档 TTL）
- 可调用 `POST /authCenter/clearCache` 立即清空
- 或在管理后台保存后**主动调用** `CloudPlatformHelper.clearAllCache()`

### Q7. 业务方想自定义 Controller 返回结构

直接在自身工程定义**同路径**的 Controller，Spring 会优先加载业务方 Bean（SDK 用的是默认 `@RestController`，无 `@Primary`）。

```java
@RestController
@RequestMapping("/sso")
public class MySsoController extends CloudTokenSsoClientController {
    // 继承后可重写任意方法，或在父类方法上加切面
}
```

或完全独立写：

```java
@RestController
@RequestMapping("/authCenter")
public class MyAuthCenterController {

    @GetMapping("/getLoginUserInfo")
    public R<MyUserInfoVo> getLoginUserInfo() {
        CloudUserInfoVo vo = CloudPlatformHelper.getUserInfo();
        return R.ok(convert(vo));
    }
}
```

### Q8. 怎么禁用 SDK 内置的某个 Controller

把 `sa-token.expose-controller` 设为 `false` 会**整体**关闭 `/sso/*`、`/authCenter/*`、`/authCenter/oss/*` 全部内置 Controller。如需**部分禁用**，请在自己工程里定义同名 Controller 完全覆盖（不调用父类方法即可）。

### Q9. 操作日志里有敏感字段怎么办

`operParam` 字段由业务方传入，**自行脱敏**：

```java
bo.setPassword("******");    // 提交前先脱敏
CloudOperLogRecorder.record(... .operParam(JsonUtils.toJsonString(bo)));
```
